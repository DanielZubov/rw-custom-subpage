# RW-CSP (Remnawave Custom Subscription Page)

Кастомная замена штатной `remnawave/subscription-page` для панели
[Remnawave](https://remna.st). Сохраняет всю базовую логику (ссылка на
подписку, список приложений), но:

- своё фирменное оформление (цвета/лого/тексты редактируются без кода — через `/admin`);
- отдельная вкладка **«Роутер (OpenWRT)»**, которая появляется автоматически,
  если у пользователя в Remnawave стоит тег `ROUTER` (или он состоит в
  Internal Squad с таким словом в названии) — с инструкцией по установке
  Podkop/Forkop, ссылкой на подписку и списком его персональных ключей;
- всё завёрнуто в один Docker-контейнер, деплой — `docker compose up -d`.

## Как это работает

Сервис сам определяет, кто к нему пришёл, по заголовку `User-Agent`:

```
Запрос на /:shortUuid
        │
        ├─ браузер (UA содержит "Mozilla") ──► рисуем HTML-страницу
        │                                       (бренд, гайд по приложениям,
        │                                        вкладка «Роутер»)
        │
        └─ не браузер (Happ/INCY/Podkop/...) ──► прозрачно пробрасываем запрос
                                                   на панель /api/sub/{shortUuid}
                                                   и отдаём ответ как есть —
                                                   байт в байт, с теми же
                                                   заголовками (Content-Type,
                                                   profile-title и т.п.)
```

Это важно: панель отдаёт разный формат ответа в зависимости от `User-Agent`
(Mihomo/Xray-json/Sing-box/Base64/HTML-страница для браузера), и приложения
вроде Happ ожидают получить по этому адресу **именно сырой конфиг**, а не
HTML. Поэтому сервис не просто рисует страницу для всех подряд — он либо
отдаёт человеку красивый UI, либо прозрачно пропускает машинный запрос к
панели дальше.

### Важно: **это не замена панели**, а отдельный лёгкий сервис страницы подписки, который:

1. По `shortUuid` из ссылки подписки (`/api/users/by-short-uuid/{shortUuid}`,
   с вашим API-токеном) узнаёт `tag`, активные `Internal Squad`ы и числовой
   `id` пользователя — отсюда решение, показывать вкладку «Роутер» или нет.
2. Для вкладки «Роутер» получает настоящие ключи пользователя через
   официальную ручку `GET /api/subscriptions/connection-keys/{userId}`
   (тоже требует токен) — это ровно то же, что видно в самой панели,
   без угадывания формата и без риска получить служебную заглушку.
3. Рисует HTML-страницу в вашем брендинге — но только для браузеров;
   остальным (см. выше) пробрасывает запрос напрямую на панель.

## Быстрый старт

```bash
cd /opt
git clone https://github.com/DanielZubov/rw-custom-subpage.git
cd rw-custom-subpage
cp .env.example .env
# отредактируйте .env: REMNAWAVE_API_URL, REMNAWAVE_API_TOKEN, SUB_PUBLIC_DOMAIN,
# ADMIN_LOGIN / ADMIN_PASSWORD

docker compose up -d --build
```

Проверка: `http://<хост>:3010/<shortUuid любого реального пользователя>`.

### Где взять `REMNAWAVE_API_TOKEN`

Панель → **Settings → API Tokens** → создать токен. Сервису достаточно прав
на чтение пользователей (`users:read` / аналог в вашей версии панели).
Токен используется только на бэкенде этого сервиса и никогда не отдаётся в
браузер.

### Подключение к сети Remnawave

Если панель и этот сервис — в одном docker-compose проекте, добавьте
`rw-custom-subpage` в тот же `docker-compose.yml`, что и `remnawave`, и укажите
`REMNAWAVE_API_URL=http://remnawave:3000` (имя контейнера панели во внутренней
сети). Если это отдельный проект — используйте `external network` (см.
`docker-compose.yml` в репозитории) или публичный HTTPS-адрес панели.

## Замена штатной subscription-page в реверс-прокси

В настройках вашего Caddy/Nginx, где раньше запросы браузера на
`SUB_PUBLIC_DOMAIN` проксировались на `remnawave-subscription-page:3010`,
поменяйте upstream на `rw-custom-subpage:3010`. Пример для Caddy:

```caddyfile
sub.example.com {
    reverse_proxy rw-custom-subpage:3010
}
```

Запросы не от браузера (по `User-Agent` от Xray-клиентов, Happ, Podkop и
т.п.) панель Remnawave, как и раньше, обслуживает сама по `/api/sub/...` —
их трогать не нужно.

## Приложение получает заглушку «Ой-ой, что-то пошло не так»

Это ответ самой панели: она узнала пользователя (трафик и срок в профиле
верные), но не отдала ключи. Панель решает это по заголовкам запроса: `x-hwid`,
`x-device-os`, `x-device-model` (лимит устройств HWID), `User-Agent` и IP клиента.
Сервис пробрасывает их панели как есть (+ `X-Forwarded-For`, `X-Real-IP`,
`X-Forwarded-Proto: https`), поэтому панель видит настоящее устройство.

Если заглушка осталась, сравните ответы панели напрямую:

```bash
SUB=https://ВАШ-ДОМЕН-ПАНЕЛИ/api/sub/SHORT_UUID
# без HWID-заголовков
curl -s -H 'User-Agent: Happ/4.6.0/Android/1' "$SUB" | base64 -d | head -c 300; echo
# как реальный Happ
curl -s -H 'User-Agent: Happ/4.6.0/Android/1' -H 'x-hwid: test123' \
  -H 'x-device-os: Android' -H 'x-device-model: Pixel' -H 'x-ver-os: 14' \
  "$SUB" | base64 -d | head -c 300; echo
```

Если в первом случае заглушка, а во втором реальные ключи — причина в HWID или в
правилах ответа панели (Настройки → Подписки → «Свои примечания» / правила).

## Загрузка логотипа: ошибка 413

`413 Request Entity Too Large` приходит не от приложения (оно принимает файлы до
2 МБ и в этом случае пишет строку в `docker logs`), а от какого-то прокси на пути
запроса. Если в логах контейнера пусто — запрос до него не дошёл.

Traefik сам по себе размер тела не ограничивает (только если вы не добавили
middleware `buffering` с `maxRequestBodyBytes`). Страницу с надписью nginx
отдаёт другой прокси перед Traefik или вместо него: nginx на хосте, Nginx Proxy
Manager, CDN-узел для домена вида `cdn.sub.example.com` и т.п.

Как найти виновника — отправьте тестовый файл и посмотрите заголовки ответа:

```bash
head -c 3000000 /dev/zero > /tmp/big.bin
curl -s -D - -o /dev/null -u ADMIN_LOGIN:ADMIN_PASSWORD \
  -F "logoFile=@/tmp/big.bin;type=image/png" https://ВАШ-ДОМЕН/admin
```

- `HTTP/2 400` и `x-powered-by: Express` — запрос дошёл до приложения (файл
  больше 2 МБ, это нормальный отказ приложения), прокси на пути ни при чём;
- `413` и `server: nginx` (или `cloudflare`) — лимит стоит на этом прокси:
  добавьте в его конфиг `client_max_body_size 5m;` (в Nginx Proxy Manager —
  Advanced → Custom Nginx Configuration).

Быстрый обходной путь: открыть админку напрямую, минуя все прокси —
`http://IP-сервера:3011/admin` (порт из `docker-compose.yml`). Файлы больше
900 КБ в форме отсекаются ещё до отправки.

## Домен и заголовки подписки (CDN, Happ, INCY)

В `/admin` → «Домен и заголовки подписки»:

- **Домен в ссылке подписки** — подставляется в кнопки «Добавить подписку»,
  отображаемую ссылку и заголовок `profile-web-page-url`. Удобно, когда клиентам
  нужно отдавать CDN-домен (например, `cdn.sub.example.com`) для обхода белых
  списков. Пусто — берётся `SUB_PUBLIC_DOMAIN` из `.env`.
- **profile-title, announce, profile-update-interval** — переписываются в ответе
  для приложений (Happ, INCY и др.). Поддерживается синтаксис шаблонов панели: `rwEncodeBase64:`, `{{DAYS_LEFT}}`, `{{USERNAME}}`, `{{STATUS:ACTIVE=...|EXPIRED=...}}` и др.
  Пустое поле — заголовок остаётся как отдала панель.
- **Дополнительные заголовки (JSON)** — любые свои, например
  `{"support-url": "https://t.me/myvpn_support"}`.

Эти заголовки применяются только при проксировании подписки приложениям, не к
HTML-странице. Домен, указанный в настройках, должен вести на этот сервис (или
на панель) — иначе приложение не получит конфиг.

### Диагностика шифрования Happ

Если кнопка «Добавить подписку» для Happ отдаёт незашифрованную ссылку,
откройте `/admin/test-crypto` — там виден сырой ответ `crypto.happ.su`
(статус, content-type, тело) и причина сбоя. Те же данные пишутся в лог
контейнера со строкой `[cryptoLinks]`.

## Шифрованные ссылки «Добавить подписку»

Кнопка «Добавить подписку» в приложении не отдаёт пользователю сырой URL
подписки — вместо этого используется официальный механизм шифрования
каждого клиента:

- **Happ** — ссылка шифруется через официальный онлайн-энкодер
  `https://crypto.happ.su/api-v2.php` (RSA-4096, формат `happ://crypt4/...`,
  см. [документацию Happ](https://www.happ.su/main/dev-docs/crypto-link)).
  Работает из коробки, доп. настройка не нужна. Если сервис Happ недоступен
  (таймаут 3 сек) — тихий откат на обычную незашифрованную `happ://add/{url}`,
  страница не ломается.
- **INCY** — ссылка шифруется локально, без сети, форматом `incy://crypt1/...`
  (AES-256-GCM, ключ зашит в приложение и официально опубликован как npm-пакет
  [`@incy/link-encoder`](https://docs.incy.cc/en/deep-links/)). Пакет указан в
  `optionalDependencies` и ставится при `docker compose up -d --build`
  автоматически. «Опциональный» значит, что при сбое установки (например, нет
  доступа к npm) сборка не падает, а кнопка INCY откатывается на обычную
  `incy://add/{url}` без шифрования. В логах при этом будет строка
  `[cryptoLinks] Пакет @incy/link-encoder не установлен`.

  Пакет ставится на этапе сборки образа, поэтому ставить его руками внутри
  контейнера не нужно (и бесполезно: после пересоздания контейнера он пропадёт).
  Версия не зафиксирована (`*`); чтобы зафиксировать, выполните локально
  `npm install @incy/link-encoder` и закоммитьте `package.json` и
  `package-lock.json`.

В обоих случаях, если шифрование не сработало, рядом с кнопкой не будет
бейджа «🔒 secured» — так сразу видно, какая ссылка реально скрыта от
пользователя, а какая нет.

## Веб-админка (`/admin`)

Доступна по `https://ваш-домен/admin`, защищена HTTP Basic Auth
(`ADMIN_LOGIN` / `ADMIN_PASSWORD` из `.env`). Обязательно повесьте на этот
путь HTTPS и смените пароль по умолчанию.

Там редактируется:

- название бренда, заголовок вкладки, логотип, основной/акцентный цвет;
- ссылка на поддержку и текст подвала;
- список приложений на вкладке «Устройства» (JSON: `name`, `platform`, `url`);
- ключевое слово для определения «роутерных» пользователей (по умолчанию
  `ROUTER` — ищется без учёта регистра в `tag` пользователя и в названиях
  его активных Internal Squad'ов);
- инструкция по установке Podkop/Forkop на вкладке «Роутер» (поддерживается
  Markdown).

Настройки хранятся в `data/settings.json` — это смонтированный volume,
переживает пересборку образа.

## Структура репозитория

```
src/
  server.js            точка входа (Express)
  config.js             чтение .env
  remnawaveClient.js    обёртка над Remnawave API (admin + public /api/sub)
  db.js                  файловое хранилище настроек (data/settings.json)
  routes/
    subscription.js     GET /:shortUuid — сама страница подписки
    admin.js              GET/POST /admin — веб-админка
  views/                 EJS-шаблоны
public/                  CSS/JS фронтенда
Dockerfile
docker-compose.yml
.env.example
```
