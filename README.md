# LeonVPN Subscription Page

Кастомная замена штатной `remnawave/subscription-page` для панели
[Remnawave](https://remna.st). Сохраняет всю базовую логику (ссылка на
подписку, список приложений), но:

- своё фирменное оформление (цвета/лого/тексты редактируются без кода — через `/admin`);
- отдельная вкладка **«Роутер (OpenWRT)»**, которая появляется автоматически,
  если у пользователя в Remnawave стоит тег `ROUTER` (или он состоит в
  Internal Squad с таким словом в названии) — с инструкцией по установке
  Podkop/Forkop, ссылкой на подписку и списком его персональных ключей;
- всё завёрнуто в один Docker-контейнер, деплой — `docker compose up -d`.

## Как это работает

Сервис сам определяет, кто к нему пришёл, по заголовку `User-Agent`:

```
Запрос на /:shortUuid
        │
        ├─ браузер (UA содержит "Mozilla") ──► рисуем HTML-страницу
        │                                       (бренд, гайд по приложениям,
        │                                        вкладка «Роутер»)
        │
        └─ не браузер (Happ/INCY/Podkop/...) ──► прозрачно пробрасываем запрос
                                                   на панель /api/sub/{shortUuid}
                                                   и отдаём ответ как есть —
                                                   байт в байт, с теми же
                                                   заголовками (Content-Type,
                                                   profile-title и т.п.)
```

Это важно: панель отдаёт разный формат ответа в зависимости от `User-Agent`
(Mihomo/Xray-json/Sing-box/Base64/HTML-страница для браузера), и приложения
вроде Happ ожидают получить по этому адресу **именно сырой конфиг**, а не
HTML. Поэтому сервис не просто рисует страницу для всех подряд — он либо
отдаёт человеку красивый UI, либо прозрачно пропускает машинный запрос к
панели дальше.

### Один домен или два — выбирайте сами

Благодаря проксированию **можно использовать один и тот же домен и для
людей, и для приложений** — укажите его и в `SUB_PUBLIC_DOMAIN` вашего
`.env`, и в `SUB_PUBLIC_DOMAIN` самой панели Remnawave. Тогда ссылка на
подписку, которую бот выдаёт пользователю, будет открываться красивой
страницей в браузере и при этом нормально подхватываться в Happ/INCY/Podkop.

Можно и как раньше, через два домена (например, `sub.example.com` — для этой
красивой страницы, `cdn.sub.example.com` — отдельный домен, который Traefik
реверс-проксит прямо на панель). В этом случае в `.env` этого сервиса
`SUB_PUBLIC_DOMAIN` должен совпадать **с тем доменом, который реально
обслуживает машинные запросы** (т.е. с `SUB_PUBLIC_DOMAIN` самой панели) —
иначе кнопка «Добавить подписку» и отображаемая ссылка будут вести на адрес,
который панель не обслуживает напрямую, и приложение получит ошибку вида
«неизвестный тип контента». Два домена в такой схеме не обязаны совпадать
друг с другом, но домен **этого** сервиса, прописанный в его `.env`, обязан
быть тем доменом, с которого реально отдаётся рабочая подписка — своим
собственным (если включено проксирование выше) или доменом панели.

Важно: **это не замена панели**, а отдельный лёгкий сервис, который:

1. По `shortUuid` из ссылки подписки (`/api/users/by-short-uuid/{shortUuid}`,
   с вашим API-токеном) узнаёт `tag`, активные `Internal Squad`ы и числовой
   `id` пользователя — отсюда решение, показывать вкладку «Роутер» или нет.
2. Для вкладки «Роутер» получает настоящие ключи пользователя через
   официальную ручку `GET /api/subscriptions/connection-keys/{userId}`
   (тоже требует токен) — это ровно то же, что видно в самой панели,
   без угадывания формата и без риска получить служебную заглушку.
3. Рисует HTML-страницу в вашем брендинге — но только для браузеров;
   остальным (см. выше) пробрасывает запрос напрямую на панель.

## Быстрый старт

```bash
git clone <этот репозиторий>
cd leonvpn-subpage
cp .env.example .env
# отредактируйте .env: REMNAWAVE_API_URL, REMNAWAVE_API_TOKEN, SUB_PUBLIC_DOMAIN,
# ADMIN_LOGIN / ADMIN_PASSWORD

docker compose up -d --build
```

Проверка: `http://<хост>:3010/<shortUuid любого реального пользователя>`.

### Где взять `REMNAWAVE_API_TOKEN`

Панель → **Settings → API Tokens** → создать токен. Сервису достаточно прав
на чтение пользователей (`users:read` / аналог в вашей версии панели).
Токен используется только на бэкенде этого сервиса и никогда не отдаётся в
браузер.

### Подключение к сети Remnawave

Если панель и этот сервис — в одном docker-compose проекте, добавьте
`leonvpn-subpage` в тот же `docker-compose.yml`, что и `remnawave`, и укажите
`REMNAWAVE_API_URL=http://remnawave:3000` (имя контейнера панели во внутренней
сети). Если это отдельный проект — используйте `external network` (см.
`docker-compose.yml` в репозитории) или публичный HTTPS-адрес панели.

## Замена штатной subscription-page в реверс-прокси

В настройках вашего Caddy/Nginx, где раньше запросы браузера на
`SUB_PUBLIC_DOMAIN` проксировались на `remnawave-subscription-page:3010`,
поменяйте upstream на `leonvpn-subpage:3010`. Пример для Caddy:

```caddyfile
sub.leonvpn.example {
    reverse_proxy leonvpn-subpage:3010
}
```

Запросы не от браузера (по `User-Agent` от Xray-клиентов, Happ, Podkop и
т.п.) панель Remnawave, как и раньше, обслуживает сама по `/api/sub/...` —
их трогать не нужно.

## Шифрованные ссылки «Добавить подписку»

Кнопка «Добавить подписку» в приложении не отдаёт пользователю сырой URL
подписки — вместо этого используется официальный механизм шифрования
каждого клиента:

- **Happ** — ссылка шифруется через официальный онлайн-энкодер
  `https://crypto.happ.su/api-v2.php` (RSA-4096, формат `happ://crypt4/...`,
  см. [документацию Happ](https://www.happ.su/main/dev-docs/crypto-link)).
  Работает из коробки, доп. настройка не нужна. Если сервис Happ недоступен
  (таймаут 3 сек) — тихий откат на обычную незашифрованную `happ://add/{url}`,
  страница не ломается.
- **INCY** — ссылка шифруется локально, без сети, форматом `incy://crypt1/...`
  (AES-256-GCM, ключ зашит в приложение и официально опубликован как npm-пакет
  [`@incy/link-encoder`](https://docs.incy.cc/en/deep-links/)). Этот пакет
  **не входит** в обязательные зависимости (чтобы сборка образа не зависела
  от npm-пакета сторонней компании). Чтобы включить шифрование для INCY:
  ```bash
  npm install @incy/link-encoder
  docker compose up -d --build
  ```
  Без пакета кнопка для INCY просто откатывается на обычную `incy://add/{url}`
  (тоже рабочую, но без шифрования URL).

В обоих случаях, если шифрование не сработало, рядом с кнопкой не будет
бейджа «🔒 зашифровано» — так сразу видно, какая ссылка реально скрыта от
пользователя, а какая нет.

## Веб-админка (`/admin`)

Доступна по `https://ваш-домен/admin`, защищена HTTP Basic Auth
(`ADMIN_LOGIN` / `ADMIN_PASSWORD` из `.env`). Обязательно повесьте на этот
путь HTTPS и смените пароль по умолчанию.

Там редактируется:

- название бренда, заголовок вкладки, логотип, основной/акцентный цвет;
- ссылка на поддержку и текст подвала;
- список приложений на вкладке «Устройства» (JSON: `name`, `platform`, `url`);
- ключевое слово для определения «роутерных» пользователей (по умолчанию
  `ROUTER` — ищется без учёта регистра в `tag` пользователя и в названиях
  его активных Internal Squad'ов);
- инструкция по установке Podkop/Forkop на вкладке «Роутер» (поддерживается
  Markdown).

Настройки хранятся в `data/settings.json` — это смонтированный volume,
переживает пересборку образа.

## Структура репозитория

```
src/
  server.js            точка входа (Express)
  config.js             чтение .env
  remnawaveClient.js    обёртка над Remnawave API (admin + public /api/sub)
  db.js                  файловое хранилище настроек (data/settings.json)
  routes/
    subscription.js     GET /:shortUuid — сама страница подписки
    admin.js              GET/POST /admin — веб-админка
  views/                 EJS-шаблоны
public/                  CSS/JS фронтенда
Dockerfile
docker-compose.yml
.env.example
```

## Как это расширять дальше

Технически стек — Node.js/Express/EJS, без сборки фронтенда, поэтому любой
человек (в том числе не программист, через Claude) может дальше просить
поправить конкретный `.ejs`/`.css` файл, не трогая остальное. Дорожная карта,
если понадобится больше «кастомизируемости»:

- вынести `apps` и цвета в drag-and-drop UI вместо JSON-поля;
- добавить загрузку логотипа файлом (сейчас — только по ссылке);
- несколько тем/пресетов оформления с превью в админке;
- поддержка нескольких брендов (мульти-тенант) на одном контейнере.
